## 0. Реестр ключевых решений (разрешение противоречий)

| # | Решение | Почему (одной строкой) |
|---|---|---|
| Р1 | Имя — **Graphite**: `graphite.exe`, `graphite-mcp.exe`, pipe `\\.\pipe\graphite-core`, служебная папка `.graphite/` | Имя вшивается в пути/пайпы до первого коммита; метафора и дизайн-идентичность совпадают |

| Р8 | Редактор — **CodeMirror 6 live-preview**; TipTap — эксперимент за флагом в v2; **никакой канонизации файла при сохранении** | Текст = истина: класс багов round-trip исчезает; канонизация ломала бы `old_string`/`rev` агента |

## 1. Видение и суть продукта

### 1.1 Позиционирование

**«Заметочник, который не хранит мысли, а доводит их до результата: ты бросаешь в него искры, твой собственный ИИ-ассистент через MCP выжимает из них планы, а всё это навсегда остаётся обычными markdown-файлами в твоей папке».**

Рыночная клетка «plain-файлы у пользователя + первоклассный встроенный MCP + конвейер идея→план + красота уровня Linear» пуста (июль 2026): Obsidian держит файлы, но отдал ИИ комьюнити-конструктору; Tana/Notion/Reflect держат агентный UX, но забрали данные в облако. Мы садимся ровно в эту клетку.

### 1.2 Пользователь и JTBD

Пользователь №1 (реальный, не персона): соло-билдер на Windows 11, десятки параллельных проектов, Claude Code открыт весь день. Мыслит быстрее, чем оформляет; идеи умирают в чатах и случайных .txt. Не нужен архив-Zettelkasten — нужен **конвейер: искра → проработанная идея → план → выполнено**.

| # | Когда… | Хочу… | Чтобы… |
|---|---|---|---|
| J1 (главный) | у меня сырая мысль | сбросить за 5 секунд, позже сказать ассистенту «доведи до плана» | идея стала пошаговым планом без ручного оформления |
| J2 | возвращаюсь к заметке | увидеть, чего в идее не хватает и что система «додумала» | не начинать обдумывание с нуля |
| J3 | заметок много | чтобы похожие сами находили друг друга | знание копилось, а не гнило |
| J4 | работаю в Claude Code | видеть заметки как родную рабочую поверхность ассистента | «посмотри мои идеи и распланируй» работало буквально |
| J5 | план принят | всегда видеть один следующий шаг и прогресс | не терять импульс между сессиями |
| J6 | думаю о будущем данных | обычные markdown-файлы в моей папке | снёс приложение — всё осталось и читается |

### 1.3 Конвейер зрелости (ядро продукта)

Каждая заметка живёт в конвейере `inbox → shaping → planned → active → done | iced` (§6.3). Статус хранится во frontmatter, виден в UI («кольцо зрелости» + пилюля статуса), отдаётся ассистенту через MCP. Переходы — только осознанные (человек или ассистент по явной команде); ассистент вправе лишь предлагать.

### 1.4 Флагманская механика «Выжимка»

Протокол доведения сырца до плана, зашитый в продукт (промпт `/graphite:distill` + тулы `distill_context`/`distill_save`), а не надежда на удачный промпт:

1. **Запуск:** кнопка «Выжать» на заметке (мост Р6: открывается терминал с ассистентом и предзаполненной командой) или фраза ассистенту напрямую.
2. **Сырьё:** `distill_context` отдаёт ассистенту заметку, связанные и похожие записи, упоминающие планы и **карту пробелов** — каких секций не хватает: цель? зачем? критерий готовности? ресурсы? сроки? риски? первый шаг?
3. **Интервью — в чате ассистента (Р5):** один вопрос за раз; каждый вопрос обязан идти с готовой гипотезой ответа («думаю, цель — X, верно?») и 2–3 вариантами; всегда доступен ответ «реши сам» — тогда ассистент принимает решения и помечает их как допущения. **Жёсткий лимит — 7 вопросов**, дальше черновик обязателен: выжимка не превращается в допрос.
4. **Соавтор за плечом:** после каждого ответа ассистент дописывает заметку через `note_edit(append_section)` — пользователь видит, как текст «проявляется» в открытой заметке (live-reload, подсветка `--ai-dim`).
5. **Выход — секции в самой заметке (Р4):** `Цель` / `Зачем` / `Критерии готовности` / `План` (чекбоксы, каждый шаг — одно конкретное действие) / `Риски` / `Допущения` / **`Ты об этом ещё не думал`** — вторичные следствия, будущие развилки, что понадобится позже. При `create_plan` — план разворачивается отдельной заметкой `type: plan` со связью `distilled_from`.

### 1.5 «На 5 шагов вперёд» — как механики, а не лозунг

1. **Гипотеза в каждом вопросе** — ассистент достраивает несформулированное, пользователь только рулит.
2. **Секция «Ты об этом ещё не думал»** — фирменный задел вперёд в каждой выжимке.
3. **`context_briefing`** — один MCP-вызов в начале сессии: следующий шаг по каждому активному плану, заброшенные искры, счётчик инбокса, «3 идеи недели на выжимку» (MVP, без эмбеддингов — на журнале и статусах).
4. **Ревизор** (v1) — проход по хранилищу по кнопке/расписанию (headless `claude -p`): заброшенные искры, дубли, непроставленные связи → одна заметка-дайджест, никаких пушей.
5. **Автосвязи/«Похожие»** (v1) — локальные эмбеддинги, панель похожих, `link_pass`.

### 1.6 Принципы «никогда»

1. Никогда — облако, аккаунты, телеметрия. Данные = папка пользователя. Сеть — только updater (opt-out) и разовая загрузка модели (opt-in, v1) (Р23).
2. Никогда — проприетарный формат. Тест: удалил приложение — не потерял ничего, всё читается глазами. Индексы/кэши — восстановимые.
3. Никогда — свой чат-бот, свои API-ключи, своя подписка на ИИ. Мы — лучшая рабочая поверхность для ассистента, который у пользователя уже есть.
4. Никогда — молчаливые правки ИИ. Любая мутация — журнал, дифф, откат в один клик.
5. Никогда — фичепарк. Один пользователь, один сценарий «мысль → план», глубина важнее ширины.
6. Никогда — коллаборация/мультиюзер. «Второй пользователь» ровно один — ИИ.
7. Никогда — навязчивость: ни пушей, ни туров, ни «оцените нас». Напоминания — только opt-in по `due:`.
8. Никогда — допрос вместо выжимки (лимит 7, гипотезы, «реши сам»).
9. Никогда — блокировка UI операциями ИИ. Всё асинхронно.
10. Никогда — острые углы и «полиш потом». Некрасивый экран = баг P0.

### 1.7 Критерий готовности продукта

**Тест первых 15 минут:** свежий пользователь на чистой машине ставит инсталлер, записывает сырую мысль хоткеем и одним запросом к своему ассистенту получает красивый интерактивный план без единой настройки, с диффами и откатом. Если это не выигрывается у связки «Obsidian + Claude Code» с разгромным счётом — продукт не готов. Тест прогоняется перед каждым релизом.

## 2. Название

**Graphite** — совпадает с материалом дизайна (графитовая палитра, карандаш = заметки) и даёт точную метафору механики: графит под давлением становится алмазом — сырая мысль под давлением выжимки становится планом; имя уже использовано в дизайн-спеке и не создаёт проблем для персонального локального продукта.

Запасные:

1. **Distill** — прямое имя флагманской механики: перегонка сырых мыслей в эссенцию плана.
2. **Ember** — тлеющая искра идеи, которую ассистент раздувает в огонь; ложится на статус «искра/inbox».
3. **Dendra** — дерево файлов + дендриты нейронов: структура и связи в одном слове.

## 3. Ключевые пользовательские сценарии

### 3.1 Жизненный цикл идеи (канон)

| Статус | Колонка | Что происходит | Условие выхода |
|---|---|---|---|
| `inbox` | Входящие | Сырьё: 1–3 строки по Ctrl+Alt+Space или из чата ассистента. Ничего не требуется, кроме «записать» | Решили прорабатывать (или лёд) |
| `shaping` | Проработка | Выжимка (S2): Цель/Зачем/Критерии/Риски; связи с существующим | Ясны конечная цель и ценность |
| `planned` | План | Заметка-план: цель, критерии готовности, этапы; критика рисков (S10) | План разбит на задачи |
| `active` | В работе | Чекбоксы, прогресс, «что дальше» (S4), обновление статусов текстом (S6) | Критерии готовности закрыты |
| `done` | Готово | Ретро (S12); уроки утекают связями в новые проекты | — |
| `iced` | Лёд | Заморожено; скрыто из видов, видно поиску; разморозка → shaping | — |

Прогресс `active`-записи агрегируется из чекбоксов её самой и под-дерева (правило дедупликации — §6.6).

### 3.2 Мост UI → ассистент (механика запуска, Р6)

- **Обнаружение:** при старте и в настройках — поиск `claude` в PATH (+ конфигурируемый путь). Найден → кнопки активны; не найден → кнопки ведут на «скопировать команду» + короткая инструкция.
- **Запуск:** кнопки «Выжать», «Распланировать инбокс», «Недельное ревью» открывают терминал (Windows Terminal, фолбэк conhost; шаблон команды конфигурируем) с командой вида `claude "/graphite:distill id:01J8QZ…"`. Интервью идёт в терминале; результат «проявляется» в заметке через live-reload.
- **Прогресс в UI:** пульс MCP-индикатора в статусбаре, живые карточки в AI-ленте, полоска «Изменено ассистентом — показать дифф» в заметке.
- **Headless** `claude -p` (без интерактива) — только для батч-задач без вопросов: ревизор, ночной бриф (v1).

### 3.3 Сценарии (цепочка тулов → эффект в UI → версия)

- **S1. Захват искры** [MVP] — Ctrl+Alt+Space из любого приложения → мини-окно → Enter. Файл падает в `Входящие/` со `status: inbox`. UI: тост, бейдж инбокса пульсирует.
- **S2. «Выжми мою сырую мысль»** [MVP, флагман] — `/graphite:distill`: `distill_context` → интервью (≤7 вопросов с гипотезами) → после каждого ответа `note_edit(append_section)` → `distill_save` (валидация секций, `set_status: shaping|planned`, опционально план). UI: секции появляются с fade-in и меткой `--ai`, кольцо зрелости анимированно растёт.
- **S3. «Посмотри мои идеи и распланируй до конечной цели»** [MVP] — `/graphite:plan_from_ideas`: чтение `vault://inbox` + `search` → ≤3 уточняющих вопроса → `plan_create(sources: […])` → `link_add(distilled_from)` → `set_status(planned)` → `ui_open_note(план)`. UI: в дереве вырастает план, открывается сам, рендерится этапами с чекбоксами и «следующим шагом».
- **S4. «Что мне делать дальше по X»** [MVP] — `vault_tree` → `note_read(План)` → `tasks_query(scope: X, open)` → `plan_progress` → ответ в чате: 1–3 шага с обоснованием; опционально `task_check`/`ui_flash_note`.
- **S5. «Разбери инбокс»** [MVP; в review-режиме — v1] — `search(status:inbox)` → классификация → `note_move`/`link_add`/`set_status` пачкой; протокол MVP: сперва показать список решений в чате, применять после «да». UI: записи разлетаются по дереву, инбокс пустеет до состояния «чисто».
- **S6. «Вот что я сделал: …» свободным текстом** [MVP] — `tasks_query(open)` → fuzzy-сопоставление → `task_check(set)`; неоднозначные — переспросить списком. UI: чекбоксы прощёлкиваются один за другим, прогресс-бар ползёт.
- **S7. «Собери дайджест недели» / недельное ревью** [MVP] — `activity_get(-7d)` + `plan_progress(all_active)` + `tasks_query(closed)` → заметка-дайджест: новое/продвинулось/закрыто/зависло + 3 предложения. UI: открывается кликабельный дайджест.
- **S8. «Верни меня в контекст»** [MVP] — `context_briefing` → «остановился на…, висит…, горит…» → `ui_flash_note` трёх ключевых.
- **S9. «Найди похожее и свяжи»** [v1] — `similar_notes` → отсев → `link_add(context: почему)` → рёбра дорисовываются, у вторых записей появляются бэклинки.
- **S10. «Покритикуй мой план»** [MVP] — `note_read` + `links_get` → поиск нереалистичных сроков, туманных этапов, отсутствующих критериев → `note_edit(append_section: «Риски и слабые места»)`.
- **S11. «Оформи поток сознания по-человечески»** [MVP] — `note_read` → `note_edit(replace)` со структурой; правило: переформулировать можно, выкидывать нельзя (исходник в истории). UI: тост «Сравнить с исходником» (дифф).
- **S12. «Ретро по проекту»** [MVP] — `activity_get(scope, всё время)` + `plan_progress` → заметка «Ретро»: удалось/тормозило/уроки.
- **S13. «Заморозь мёртвое»** [MVP-лайт: список в чате; v1: review-панель] — `search(без движения >60д)` → кандидаты с причинами → `set_status(iced)` только после подтверждения.
- **S14. Дейлик и зеркала задач** [v1] — `daily_note` + задачи-зеркала `![[План#^t-id]]`: чекнул в дневнике — закрылось в источнике.
- **S15. Проактивный утренний бриф** [v1] — cron: headless `claude -p` → `context_briefing` + `tasks_query(today, overdue)` → дневная заметка готова к открытию ноутбука.
- **S16. Сессии как артефакты** [v2] — `session_log_append`: транскрипт брейншторма сохраняется под-заметкой, провенанс каждого пункта плана.

## 6. Модель данных

### 6.1 Принципы

1. **Файлы — единственный источник истины.** Markdown в папке-vault; любая БД — перестраиваемый кэш («Пересобрать индекс» валидна всегда).
2. **Совместимость с Obsidian-конвенциями**: frontmatter, `[[wiki]]`, `#теги`, `^block-id` — модели уже «знают» формат.
3. **Проектируем под «грязные» записи извне**: внешний редактор, Claude Code Edit, скрипты — штатные писатели.
4. **Никакой канонизации при сохранении** (Р8): файл хранится как набран.

### 6.2 Формат заметки

Markdown (CommonMark + GFM) + YAML frontmatter. UTF-8, LF (нормализация при создании файлов приложением; чужие CRLF не переписываются молча).

```yaml
---
id: 01J1Z3AC9RQK7T2M5X8VBN4WPD   # ULID, выдаётся при создании/индексации, неизменяемый
type: note                        # note|plan|project|task|journal
title: Сделать прототип поиска    # опционально: имя файла — основной заголовок
aliases: [search-mvp]
tags: [проект/заметки, mvp]       # + инлайновые #теги в тексте; индекс объединяет
status: shaping                   # словарь §6.3
priority: high                    # low|normal|high|urgent (опц.)
due: 2026-07-10                   # опц.
goal: Первые 1000 читателей       # plan
target_date: 2026-10-01           # plan
rel:
  part_of: ["[[id:01J0…|Приложение заметок]]"]
  depends_on: ["[[Индекс SQLite]]"]
sort: 3.5                         # дробный порядок среди детей (нет — алфавит)
created: 2026-07-03T12:00:00+03:00
updated: 2026-07-03T14:30:00+03:00
x-любое-поле: значение            # произвольные свойства разрешены
---
Тело в markdown. Абзац с якорем. ^b3k9q
```

Зарезервированное ядро полей: `id, type, title, aliases, tags, status, priority, due, scheduled, goal, target_date, rel, sort, created, updated`. Схемы по типу — `.graphite/types.yaml` (ожидаемые поля, дефолты); валидация **мягкая** (подсветка, не запрет). `title` спасает заголовки с запрещёнными в Windows символами.

### 6.3 Статусы (единый канон, Р3)

| Тип | Поле | Словарь | Правила переходов |
|---|---|---|---|
| note, project, plan | `status` | `inbox → shaping → planned → active → done`; `iced` — из любого, разморозка → `shaping` | Только явной командой человека или ассистента; ассистент понижение не делает, повышение — предлагает |
| task (файл и инлайн-чекбокс) | `status` / чекбокс | `todo → doing → done`; `dropped` | `task_check` — set-семантика, не toggle |
| journal | — | без статуса | — |

Русские подписи колонок: Входящие · Проработка · План · В работе · Готово · Лёд. «Пауза» проекта = `iced` (отдельного значения нет — один словарь без исключений).

### 6.4 Вложенность на диске (Р2)

Лист — файл `Тёмная тема.md`. Появился первый ребёнок → атомарная транзакция: `Идея.md` → `Идея/_index.md`, дети внутри. Обратно по умолчанию не схлопываем. Порядок детей — `sort` (дробный индекс: перестановка = правка одного файла).

```
Vault/
  .graphite/            # индекс, журнал, история, настройки (вне бэкапа не обязательны)
  .trash/               # мягкое удаление, 30 дней
  _assets/              # вложения
  Входящие/
  Journal/2026/07/2026-07-03.md        # v1
  Проекты/
    Приложение заметок/
      _index.md
      Идеи/
        _index.md
        Тёмная тема.md
      План MVP.md
```

### 6.5 Связи

- Синтаксис: `[[Заголовок]]`, `[[Заголовок#Секция]]`, `[[Заголовок#^b3k9q]]`, `[[Заголовок|текст]]`, id-форма `[[id:01J…|текст]]` (рекомендована агенту — железно стабильна).
- **Резолвинг (порядок):** точный путь → `id:` → уникальный title/alias. Нормализация: casefold, `ё→е`, Unicode NFC, трим. Неуникальный title → в UI пикер, в MCP `AMBIGUOUS` с кандидатами. Битые ссылки — отчёт «Разорванные связи» с автопочинкой по alias/истории.
- **Бэклинки не хранятся в файлах** — только таблица `links` индекса (Р15).
- **Типизированные связи** — `rel:` во frontmatter. Реестр: `related` (дефолт), `part_of`, `depends_on`, `blocks`, `contradicts`, `distilled_from`, `collected_in`; кастомные — только с префиксом `x-`. Обратные представления (`has_part`, `blocked_by`, …) вычисляет индекс.
- Эмбеды `![[Заметка]]`, `![[Заметка#Секция]]` — трансклюзия (v1): глубина ≤5, цикл → рендер ссылкой с предупреждением.

### 6.6 Задачи (Р22)

Единый синтаксис инлайн-задачи в любой заметке:

```
- [ ] Выбрать платформу @due(2026-07-15) @p(high) @every(mon) ^t-8f2k
```

- Якорь `^t-<4–6 base32>` — стабильный ID; проставляется приложением/ядром при индексации, если отсутствует (для задач планов — обязателен).
- `@due(дата)`, `@p(low|normal|high|urgent)`, `@every(…)` — зарезервирован (парсится, исполняется в v2).
- Индекс парсит их в таблицу `tasks` с адресом «файл + якорь + строка» — задачи адресуемы для `tasks_query`/`task_check`.
- **Агрегация прогресса (без двойного счёта):** план считает только собственные чекбоксы; проект = сумма планов и task-файлов своего под-дерева, каждая задача учитывается один раз по файлу-источнику; **зеркала не считаются**.
- **Зеркала (v1):** `![[План#^t-8f2k]]` в daily note рендерится живым чекбоксом; клик пишет в файл-источник.

### 6.7 Вложения

- Путь: `_assets/YYYY/MM/<ulid>.<ext>`; пути от корня vault — move/rename заметок их не трогает.
- Ctrl+V картинки/файла → сохранение + вставка `![](_assets/…)`; **дедуп по blake3** (совпал хэш — переиспользуем существующий файл).
- GC осиротевших — только отчётом Ревизора (v1), никогда автоматически. Не-картинки (PDF и пр.) — та же схема, рендер ссылкой. Агент видит `_assets/` как обычные файлы.

### 6.8 История и undo (Р7)

**Журнал** `.graphite/journal/YYYY-MM.jsonl` — append-only, одна запись на операцию:

```json
{"op_id":"01J…","ts":"2026-07-03T14:02:11+03:00","actor":"assistant","session":"mcp-01J…",
 "tool":"note_edit","summary":"append_section «Риски» → «Идея OmniApp»",
 "files":[{"path":"Проекты/OmniApp/Идея.md","before":"blake3:ab12…","after":"blake3:cd34…"}]}
```

**Снапшоты** `.graphite/history/objects/<2-префикс>/<blake3>` — полные версии файлов, zstd, content-addressed (дедуп бесплатно; текст дёшев — ретеншн бессрочный, GC опционален). Фиксация: каждая MCP-мутация; каждое сохранение UI (автосейв debounce 500 мс — before/after); внешняя правка (watcher пишет op `external` с before из последнего известного снапшота).

**Матрица undo (три системы, правила взаимодействия):**

| Действие пользователя | Что откатывается |
|---|---|
| Ctrl+Z в редакторе | Только буфер текущей заметки (стек CM6). Применённые к диску правки ассистента в стек **не попадают** — они приезжают как reload и отменяются только через ленту |
| «Отменить» на карточке AI-ленты | Операция целиком (все её файлы) восстановлением before-снапшотов; если файл менялся после — 3-way, пересечение → конфликт-панель. Отменённое остаётся в ленте с пометкой, повторный клик возвращает |
| «Отменить сессию» | Все операции сессии в обратном порядке одним действием |
| Корзина | `note_delete` кладёт в `.trash/` (30 дней); восстановление — undo-карточкой или `note_restore` |

Правило: откат при «грязном» буфере той же заметки → сначала предложение сохранить/сбросить буфер.

### 6.9 Поисковый индекс

Один файл `.graphite/index.db` (SQLite, WAL), целиком производный:

- `notes(id, path, title, type, status, mtime, hash, props JSON)` — generated columns на горячие поля (`status`, `due`, `type`); произвольные свойства — `json_extract`.
- `links(src_id, dst_id, dst_raw, rel_type, block)` — граф и бэклинки.
- `blocks(note_id, anchor, heading_path, text, pos)` — адресация секций (фундамент `note_edit` по секциям).
- `tasks(id, note_id, anchor, text, done, due, priority, stage)` — денормализованные задачи, включая инлайновые.
- **FTS5** по title+body: `unicode61 remove_diacritics 2` + **trigram-таблица** (устойчивость к русской морфологии без стеммера); trigram-вставки — только батчами в транзакции.
- `meta(vault_format, parser_version, embedder_version)` — при несовпадении версии парсера/эмбеддера — фоновая переиндексация/пере-эмбед.
- **v1:** sqlite-vec `vec0(embedding float[384])` по чанкам 200–400 токенов (по заголовкам, префиксы `query:`/`passage:`); брутфорс-скан до ~100k чанков (<50 мс), ANN не нужен. Гибрид: BM25 ∪ косинус → Reciprocal Rank Fusion.

### 6.10 Конкурентные правки

- Watcher: `notify` (ReadDirectoryChangesW) + debounce 300 мс + **stability-check** (два чтения с равным blake3 через интервал) — защита от неатомарных внешних писателей (Р12).
- Запись всегда атомарна: temp-файл → fsync → rename.
- **Эхо-подавление:** ядро перед записью кладёт `(path, hash)` в set с TTL и сверкой после стабилизации — свой write не вызывает реиндекс-цикла; склейка «свой+чужой в одном окне» разрешается сверкой итогового hash.
- Заметка открыта и **чистая** + файл сменился → тихий reload с сохранением позиции (по якорям).
- Заметка **грязная** + файл сменился → 3-way (base = снапшот буфера на момент загрузки, Р10): непересекающиеся по границам секций правки и чистые append сливаются молча (типовой кейс: агент дописал секцию, пользователь правит другую); пересечение → конфликт-панель side-by-side, обе версии в истории. Никаких conflict-файлов, никаких локов.
- Обязательная тест-матрица: VSCode, Claude Code Edit, `git checkout` под приложением, OneDrive, Defender-скан.

### 6.11 ID, переименования, живучесть ссылок

- `id` = ULID (лексикографически сортируется по времени). Имя файла — представление, id — идентичность; индекс держит карту `id ↔ path ↔ title ↔ aliases`. Файл без id (создан извне) получает id при индексации.
- **Переименование/перенос из приложения или через MCP** — транзакция: переместить файл(ы) → переписать `[[ссылки]]` во всех ссылающихся файлах (старый title → в `aliases`) → обновить индекс → одна запись журнала. Учтён край: promotion в folder-note меняет путь под открытой вкладкой — вкладки ремапятся по id.
- **Переименование извне:** watcher матчит «пропал A, появился B» по id из frontmatter → это move, входящие ссылки чинятся.

### 6.12 Windows-края

- **MAX_PATH:** манифест `longPathsAware`, внутри ядра — `\\?\`-пути; лимит имени файла 120 символов (обрезка с «…», оригинал в `title`); запрещённые `\/:*?"<>|` → «—».
- **OneDrive/Dropbox:** детект при создании/открытии vault (маркеры пути + `FILE_ATTRIBUTE_RECALL_ON_DATA_ACCESS`) → предупреждение (placeholder-файлы, врущие mtime, гидрация при cold-scan) и рекомендация локальной папки.
- mtime не доверяем: сравнение mtime+blake3.

### 6.13 Масштаб (бюджеты)

10k заметок ≈ 30 МБ текста; FTS ~50–80 МБ; векторы (v1) ~75 МБ. Холодный полный рескан на SSD < 2 с; тёплый старт — mtime-diff, десятки мс; UI открывается сразу, индексация в фоне; FTS < 10 мс; дерево и списки — виртуализация; эмбеддинг — инкрементальная очередь с приоритетом открытого.

## 7. Интеграция с ассистентом (MCP)

### 7.1 Архитектура подключения

- `graphite-mcp.exe` — **тонкий stdio-клиент** (rmcp): весь стейт и запись — в ядре приложения через named pipe `\\.\pipe\graphite-core` (JSON-RPC, локальный токен в `.graphite/runtime.json`). Приложение не запущено → MCP-бинарь запускает `graphite.exe --hidden` (в трей) и ждёт pipe ≤10 с (Р20). Двух писателей не бывает физически.
- Подключение: Настройки → MCP-доступ → «Подключить Claude Code» — генерирует и по кнопке выполняет `claude mcp add graphite -- "<install>\graphite-mcp.exe" --vault "D:\Vault"`; тест-пинг `vault_info` тут же.
- Прямые правки файлов агентом (Edit/Write) — **легальный второй канал**: watcher ловит, журналирует как `external`, атрибуция — по Р27. `vault://conventions` прямо говорит ассистенту: «мутации — через инструменты» (поиск по индексу, ссылочная целостность, валидация, журнал).

### 7.2 Протокол

- **Адресация:** везде `ref` — `id:01J8…` (рекомендован) или `path:Проекты/Блог.md`.
- **Конверт:** `{v:"1.0", ok:true, data:{…}}` | `{v, ok:false, error:{code, message, hint}}`; коды: `NOT_FOUND | CONFLICT | VALIDATION | AMBIGUOUS | LIMIT | FORBIDDEN | UNAVAILABLE`. `hint` — машиночитаемое «что сделать» («перечитай note_read и повтори с новым rev»).
- **rev** = blake3 содержимого (16 hex) из последнего чтения; мутации с rev-защитой при расхождении возвращают `CONFLICT` + актуальный rev + дифф чужих правок; протокол агента: перечитать → пере-применить.
- **Аннотации** MCP: `readOnlyHint` / `destructiveHint` / `idempotentHint` на каждом туле.
- **Лимиты:** ответ ≤ 50 КБ (`truncated:true` + hint «section/offset»); списки — `limit/offset` (tree ≤500, search ≤50); мутации ≤ 5 rps. Идемпотентность: MVP — set-семантика (`task_check`, `link_add`, `set_status`, move/rename — повтор = no-op); `idempotency_key` + журнал ключей 24 ч — v1 (Р24).
- **Версии:** `schema_version` в `vault_info` и конверте (SemVer: minor — только добавления); `capabilities[]` — фиче-флаги (`semantic_search` появляется в v1; ассистент мягко деградирует до keyword); `vault_format` — отдельно, с автомиграциями.

### 7.3 Реестр инструментов (канон, Р25)

Поверхность — 25 тонких тулов; вся толщина в ядре (одни и те же функции vault-core). Формат ниже: аргументы → возврат; пример.

**Навигация и чтение (read-only)**

- **`vault_info`** — `{}` → `{schema_version, vault_format, root, counts:{notes, plans, tasks_open, inbox}, capabilities:[], limits, conventions_digest}`. Первый вызов сессии.
  Пример: `{}`
- **`vault_tree`** — `{root?:ref, depth?:int=2, types?:string[], limit?:int=200, offset?:int=0}` → `{nodes:[{ref, path, title, type, status, children_count, updated}], total}`.
  Пример: `{"root":"path:Проекты","depth":3}`
- **`note_read`** — `{ref, include?:("links"|"backlinks"|"children"|"tasks")[], section?:string, offset?:int=0, max_chars?:int=20000}` → `{frontmatter, content, rev, truncated?, links?, backlinks?, children?, tasks?}`.
  Пример: `{"ref":"id:01J8QZ","include":["backlinks","tasks"]}`
- **`search`** — `{query, mode?:"keyword"|"semantic"|"hybrid"="keyword", filters?:{type?, status?, tags?, path?, updated_after?, updated_before?, due_before?}, limit?:int=20, offset?}` → `{hits:[{ref, title, score, snippets[≤3×300], updated}]}`. Операторы в query: `"фраза"`, `-минус`, `tag:`, `type:`, `status:`. `semantic|hybrid` — при capability `semantic_search` (v1), иначе `UNAVAILABLE` + hint.
  Пример: `{"query":"монетизация tag:блог","filters":{"status":"shaping"},"limit":10}`
- **`links_get`** — `{ref, direction?:"out"|"in"|"both"="both", types?:string[]}` → `{out:[{to, type, context}], in:[{from, type}]}`.
  Пример: `{"ref":"id:01J8QZ"}`
- **`activity_get`** — `{since:"-7d"|datetime, scope?:ref, actor?:"user"|"assistant"|"external"|"all"="all", limit?:int=100}` → `{events:[{ts, actor, tool?, summary, refs}]}`. Из журнала.
  Пример: `{"since":"-7d","scope":"path:Проекты/Блог"}`
- **`context_briefing`** — `{}` → `{inbox_count, next_steps:[{plan, task}], stalled:[{ref, days}], overdue:[…], recent:[…], suggest_distill:[ref×3]}`. Heads-Up одной командой.
  Пример: `{}`

**Создание и правка (rev-защита)**

- **`note_create`** — `{parent?:ref, title, type?:"note", status?:"inbox", tags?:[], content?:md, template?:string}` → `{ref, path, rev}`. Уважает folder-note и шаблон типа.
  Пример: `{"parent":"path:Входящие","title":"Локальный ИИ-планировщик","content":"## Суть\n…"}`
- **`note_edit`** — `{ref, rev, ops:[{op:"replace", old_string, new_string} | {op:"append_section", heading, content} | {op:"replace_section", heading, content} | {op:"prepend", content} | {op:"set_frontmatter", key, value}]}` → `{rev_new, diff_stat:{plus, minus}}`. `old_string` обязан встречаться ровно один раз; `replace_section` по исчезнувшему заголовку → `NOT_FOUND` + hint (никогда «куда-то применить»).
  Пример: `{"ref":"id:01J8QZ","rev":"9f2a…","ops":[{"op":"append_section","heading":"Риски","content":"- зависимость от одного канала"}]}`
- **`note_move`** — `{ref, new_parent:ref, position?:number}` → `{path_new, links_rewritten}`. Линк-безопасная транзакция §6.11; дети каскадом; id неизменны.
  Пример: `{"ref":"id:01J8QZ","new_parent":"path:Проекты/Блог"}`
- **`note_rename`** — `{ref, new_title}` → `{path_new, links_updated, alias_added}`.
  Пример: `{"ref":"id:01J8QZ","new_title":"Блог: стратегия запуска"}`
- **`note_delete`** — `{ref}` → `{restore_token, backlinks_broken}`. Только мягкое: `.trash/` 30 дней; `destructiveHint`.
  Пример: `{"ref":"id:01J8QZ"}`
- **`note_restore`** — `{restore_token?|ref?}` → `{ref, path}`.
  Пример: `{"restore_token":"rt-01J…"}`
- **`set_status`** — `{ref, status, reason?}` → `{old, new}`. Валидирует словарь §6.3; сомнительный переход → `VALIDATION` + hint.
  Пример: `{"ref":"id:01J8QZ","status":"iced","reason":"нет движения 70 дней"}`

**Связи**

- **`link_add`** — `{from:ref, to:ref, type?:"related", context?:string}` → `{created:bool}` (дубль → false; обратка — из индекса, Р15).
  Пример: `{"from":"id:01J8QZ","to":"id:01J9AA","type":"depends_on","context":"запуск блога требует контент-плана"}`
- **`link_remove`** — `{from, to, type?}` → `{removed:bool}`.

**Задачи и планы**

- **`tasks_query`** — `{scope?:ref, status?:"open"|"done"|"all"="open", due_before?:date, overdue?:bool, plan?:ref, limit?:int=50}` → `{tasks:[{id, text, done, due, priority, source:{ref, anchor}, plan?, stage?}]}`. Включая инлайновые по всему vault.
  Пример: `{"overdue":true}`
- **`task_check`** — `{tasks:[{id, done:bool, note?}]}` → `{updated, progress_by_plan}`. Set-семантика (безопасный ретрай).
  Пример: `{"tasks":[{"id":"t-8f2k","done":true,"note":"выбрал Ghost"}]}`
- **`plan_create`** — `{title, goal, target_date?, parent?:ref, stages:[{title, tasks:[{text, due?}]}], sources?:ref[]}` → `{ref, task_ids:[[…]], progress:{done:0, total}}`. `sources` линкуются `distilled_from` — план помнит, из чего вырос.
  Пример: `{"title":"Запуск блога до октября","goal":"Первые 1000 читателей","stages":[{"title":"Фундамент","tasks":[{"text":"выбрать платформу"},{"text":"нарезать 20 тем","due":"2026-07-15"}]}],"sources":["id:01J8QZ"]}`
- **`plan_update`** — `{ref, rev, ops:[{op:"add_stage", title, after?} | {op:"add_task", stage, text, due?} | {op:"edit_task", task_id, text?, due?} | {op:"remove_task", task_id} | {op:"reorder", order:[…]}]}` → `{rev_new, progress}`.
- **`plan_progress`** — `{ref?, all_active?:bool=true, stalled_days?:int=7}` → по плану: `{ref, title, percent, done, total, by_stage[], overdue[], stalled[], next_tasks[≤3]}`.
  Пример: `{"all_active":true}`

**Выжимка**

- **`distill_context`** — `{ref, budget_chars?:int=30000}` → `{bundle:[{ref, role:"source"|"linked"|"similar"|"plan"|"neighbor", excerpt}], gaps:["goal","why","done_criteria","first_step",…], coverage}`. `similar`-роль — с v1; `gaps` — карта отсутствующих секций; честно сообщает, что не влезло.
  Пример: `{"ref":"id:01J8QZ"}`
- **`distill_save`** — `{ref, rev, sections:{цель, зачем, критерии_готовности, план?, риски?, допущения?, не_думал?}, set_status?:"shaping"|"planned", create_plan?:bool=false}` → `{rev_new, plan_ref?}`. Валидирует обязательные (цель, зачем, критерии, первый шаг в плане); пишет секции в исходную заметку (Р4); при `create_plan` — разворачивает план со связью `distilled_from`.
  Пример: `{"ref":"id:01J8QZ","rev":"9f2a…","sections":{"цель":"…","зачем":"…","критерии_готовности":"…","не_думал":"- через месяц упрёшься в…"},"set_status":"planned","create_plan":true}`

**UI-мост**

- **`ui_open_note`** — `{ref}` → `{ok}`; **`ui_flash_note`** — `{ref}` → `{ok}` (подсветить в дереве). GUI скрыт/закрыт → `UNAVAILABLE` с hint (не ошибка сценария).
  Пример: `{"ref":"id:01J9PL"}`

**v1:** `similar_notes {ref, k?=8, exclude_linked?=true}` · `batch_apply {ops:[{tool, args}]≤50, atomic?=true, idempotency_key}` (белый список мутаций; одна запись журнала, один узел отката) · `propose_changes {title, rationale?, ops:[…]}` → `{proposal_id}` (pending до Принять/Отклонить в UI) · `template_apply {parent?:ref, template}` · `daily_note {date?}` · `idempotency_key` на всех мутациях.
**v2:** `graph_get {ref, hops?=2, limit?=100}` · `session_log_append {ref, role, content}` · `ui_ask {question, options[]}` (если MCP даст канал).

### 7.6 Права и доверие (Р14)

- Режимы на vault: **read-only** / **auto** (дефолт: всё применяется сразу, страховка — журнал и undo) — MVP; **review** (мутации копятся как pending-предложения с инлайн-диффом Принять/Отклонить) + правило «batch>10 — всегда review» — v1.
- Приватность: папок-исключений **нет** (агент с файловым доступом их всё равно прочитает) — честная модель: приватное = отдельный vault (v1, мульти-vault); в доках — явная модель угроз.
- Атрибуция (Р27): MCP-мутации — `assistant`; правки файлами во время активной MCP-сессии — метка «внешняя правка (возможно, ассистент)»; вне сессии — `external`.

### 7.7 Как UI показывает работу ассистента

- **AI-лента** (правая панель, Ctrl+Shift+A): карточки операций, группировка по сессиям («Claude Code · 14:02 · 6 изменений»), фильтры; клик — инлайн-дифф (для планов — семантический: «+3 задачи в „Фундамент“», «отмечено 4/10»; для create — превью). Кнопки «Отменить» / «Отменить сессию» (§6.8).
- **Индикация:** пульс `◈` в статусбаре пока сессия активна (M12); точка `--ai` у изменённых и непросмотренных заметок в дереве; внутри заметки — полоска «Изменено ассистентом 2 мин назад · показать дифф», исчезает после просмотра; изменённые блоки — фон `--ai-dim` с затуханием (M13).
- **Live-эффект:** пользователь держит заметку открытой и видит, как она дописывается после каждого его ответа в чате, — «соавтор за плечом» и есть главный wow.

## 8. Техническая архитектура

### 8.1 Сводка решений

| Слой | Выбор | Отвергнуто |
|---|---|---|
| Каркас | **Tauri 2** (Rust-ядро, WebView2) | Electron (вес, старт, память; ядро было бы на Node) |
| UI | **React 19 + TypeScript 5.9 (strict) + Vite 7 + Tailwind 4** | Solid (экосистема редактора/UI — React-first) |
| Анимации | **motion 12** + CSS для микро | GSAP (императивен), react-spring |
| Редактор | **CodeMirror 6 live-preview** (Р8) | TipTap (round-trip риск; v2-эксперимент), Lexical, Milkdown |
| Истина | Markdown-файлы (frontmatter, wiki-links) | БД как истина |
| Индекс | SQLite WAL + FTS5 + trigram; **sqlite-vec — v1** | Tantivy |
| Эмбеддинги (v1) | multilingual-e5-small ONNX int8 384-dim (~112 МБ), fastembed-rs | bge-m3 (тяжёлый) |
| Запись | **vault-core — единственный писатель**; MCP — тонкий прокси по pipe | два независимых писателя |
| История | JSONL-журнал + blake3/zstd-снапшоты (Р7) | git под капотом (v1 — только sync) |
| MCP | rmcp (официальный Rust SDK), stdio | Node-сервер, HTTP (v2) |
| Дистрибуция | NSIS per-user + tauri-plugin-updater + GitHub Releases | MSIX/Store |

### 8.2 Схема слоёв

```
Claude Code ──(stdio, MCP)── graphite-mcp.exe ──(JSON-RPC, \\.\pipe\graphite-core, токен)──┐
Claude Code ──(прямые Edit/Write — легальный второй канал)────► Vault (*.md) ◄── истина ───┤
                                                                    ▲                      │
┌─ graphite.exe (Tauri 2; единственный владелец vault: single-instance + fd-lock) ─────────▼──┐
│ React 19 UI (CM6, дерево, палитра, AI-лента) ⇄ tauri-specta команды/события                 │
│                        vault-core — единственный писатель                                    │
│  writer (atomic, \\?\, эхо-set) · parser (comrak) · indexer (SQLite: FTS5+trigram[+vec v1])  │
│  watcher (notify 300ms + stability) · history (JSONL + снапшоты) · [semantics — v1]          │
└──────────────────────────────────────────────────────────────────────────────────────────────┘
```

**Инварианты:** (1) файлы — единственная истина, индекс всегда пересобираем; (2) в vault пишет только vault-core — любой обход в коде = блокер на ревью; (3) UI и MCP — равноправные клиенты одного API.

### 8.3 Процессная модель

- Один процесс-владелец: `tauri-plugin-single-instance` + эксклюзивный `fd-lock` на vault.
- `graphite-mcp.exe`: ищет pipe → нет → spawn `graphite.exe --hidden` → ждёт pipe ≤10 с → работа; не удалось → ошибка с hint. Приложение живёт в трее (закрытие окна ≠ выход).
- Автосейв UI: debounce 500 мс; каждое сохранение — снапшот-пара в history.

### 8.4 Репозиторий (Cargo + pnpm workspaces)

```
graphite/
├─ Cargo.toml                  # workspace
├─ pnpm-workspace.yaml
├─ docs/vault-format.md        # freeze формата (этап 0) + golden-фикстуры

│  ├─ history/                 # JSONL-журнал, снапшоты, undo
│  ├─ rpc/                     # named-pipe сервер + типы протокола (общие)
│  ├─ semantics/               # v1: fastembed, очередь, sqlite-vec (feature-gated)
│  └─ graphite-mcp/            # bin: rmcp stdio ⇄ pipe-клиент, автозапуск приложения
├─ apps/desktop/
```

### 8.5 Библиотеки с версиями

**Rust:** tauri `2.x (≥2.5)` + плагины v2: `single-instance`, `global-shortcut`, `updater`, `window-state`, `dialog`, `opener` (+`autostart` в v1); rusqlite `≥0.33` (`bundled`, FTS5); notify `8` + notify-debouncer-full `0.5`; comrak `≥0.39` (GFM + wikilinks); rmcp (официальный MCP Rust SDK, актуальный `0.x`); tokio `1.x`; serde `1` + serde_yml; specta `2` + tauri-specta `2`; ulid `1`; fd-lock `4`; interprocess `2`; blake3 `1`; zstd `0.13`; thiserror/anyhow. **v1:** fastembed `≥4` (ort/onnxruntime), sqlite-vec `0.1.x` (за абстракцией; фолбэк — brute-force по BLOB).

### 8.6 Производительность (бюджеты — часть спеки)

- Старт < 1 с до интерактивного дерева: окно после первого пейнта, дерево из кэша SQLite мгновенно, ядро/watcher — асинхронно после; редактор — ленивый чанк; `lto="thin"`, `codegen-units=1`.
- Quick Capture: появление окна < 150 мс.
- Поиск: p95 < 30 мс на 10k заметок; дебаунс ввода 30–50 мс; стриминг в палитру.
- Live-reload: правка агента на экране < 1 с.
- 60 fps: только transform/opacity; layout-анимации отключаются при >N видимых строк; виртуализация дерева и списков.

### 8.7 Упаковка, обновления, first-run

- `tauri build` → NSIS per-user (без UAC), ~10–15 МБ; WebView2 — bootstrapper с фиксацией минимальной версии.
- Автообновление: tauri-plugin-updater, подпись minisign, `latest.json` в GitHub Releases (приватный репо, токен в конфиге); тихая проверка при старте (opt-out), установка при выходе.
- CI: GitHub Actions (`tauri-action`): fmt/clippy/test → тег → подписанный релиз.
- **First-run flow:** (1) приветствие → создать/выбрать vault (детект OneDrive-путей → предупреждение); (2) открыть существующую папку .md как vault — неразрушающе (конвенция `_index.md` применяется только к новым узлам; полный импорт-визард — v1); (3) «Подключить ассистента»: детект `claude` → кнопка выполнить/скопировать `claude mcp add` → тест-пинг; (4) проверка глобального хоткея (занят → переназначение); (5) подсказка «первая искра: Ctrl+Alt+Space». Семантика (v1) — отдельный баннер «скачать модель ~112 МБ?» с offline-отказом и честной деградацией до FTS.

## 9. ПЛАН РЕАЛИЗАЦИИ

Соло-разработчик + ИИ-агенты. Итог MVP: **12–14 недель до личной беты**. Порядок: позвоночник (файлы→ядро→MCP) → глаза (UI) → нервы (watcher/журнал) → фирменная механика → красота на заранее заложенных токенах.

**Три красные линии (нарушение = стоп):**
1. Формат vault замораживается на этапе 0 и покрывается golden-тестами — урок Logseq зашит в процесс.
2. «Один писатель» — физический инвариант: любой обход vault-core = блокер на ревью.
3. Каждый этап заканчивается догфудом на реальном vault пользователя, не на тестовой папке; пользователь живёт в продукте с недели ~3.

### Этап 0 — Фундамент (0.5–1 нед)

**Задачи:** monorepo (Cargo + pnpm workspaces), CI (fmt/clippy/test/build + web-lint), пустой Tauri-shell собирается и подписывается; `packages/ui` с токенами §5 (палитра, радиусы, шрифты, print-css заготовка); **`docs/vault-format.md` — freeze формата** (frontmatter-ядро, статусы, задачи, связи, `_index.md`, `.graphite/`-раскладка) + golden-фикстуры (30+ файлов со всеми конструкциями, включая кириллицу/ё/длинные пути); имена вшиты (Р1); каркас i18n (строки в ресурсы, локаль ru).
**Критерии:** CI зелёный; спека формата в репо; фикстуры парсятся прототипом парсера.
**Пощупать:** тёмное пустое окно с токенами и скруглённым хромом; документ формата.

### Этап 1 — Ядро vault-core (2 нед)

**Задачи:** parser (comrak: frontmatter, wikilinks, задачи `@due/@p/^t`, секции/якоря); atomic writer (temp→fsync→rename, `\\?\`, эхо-set); ULID-карта и авто-проставление id; линк-резолвер (нормализация casefold/ё/NFC, AMBIGUOUS); SQLite-индекс (notes/links/blocks/tasks, FTS5 + trigram батчами, generated columns); транзакции rename/move/promotion с перепиской ссылок; `.trash`; property-тесты (fuzz парсера, roundtrip «parse→не трогаем файл»); CLI-обвязка (`graphite-cli create|search|move|check|reindex`).
**Критерии:** на 1k генерённых заметок: полный рескан < 2 с; rename переписывает все входящие ссылки без потерь (тест); поиск < 30 мс; golden-фикстуры зелёные.
**Пощупать:** полноценный CLI-заметочник в терминале.

### Этап 2 — MCP (1 нед)

**Задачи:** `graphite-mcp.exe` (rmcp, stdio) + pipe-протокол `rpc` + автозапуск приложения (пока — headless-заглушка ядра под тем же lock); реестр §7.3 (MVP-набор), конверт/rev/ошибки/лимиты;
журнал-записи операций (простой append уже здесь); prompts как MCP prompts (`/graphite:distill`, `/plan_from_ideas`, `/weekly_review`, `/brainstorm`, `/inbox_triage`); инструкция/скрипт `claude mcp add`; интеграционные тесты CONFLICT-протокола (агент читает rev → внешняя правка → edit → CONFLICT → перечитал → применил).
**Критерии:** сценарий «прочитай инбокс → выжми идею → создай план» проходит из Claude Code в терминале на живом vault; файлы после сессии валидны и читаются глазами; CONFLICT-протокол покрыт тестом; мутации журналируются.
**Пощупать:** флагманская ценность доказана без UI — «идея → план» из терминала на своих файлах; с этой недели начинается ежедневный догфуд через Claude Code.

### Этап 3 — UI-каркас (2.5–3 нед)

**Задачи:** главное окно (rail 48px / дерево 240–360 / вкладки-центр / правая панель 300 / статусбар 28) на токенах; дерево react-arborist (виртуализация, DnD, F2-переименование, folder-note бейджи, клавиатура); CM6 live-preview (декорации: заголовки, чекбоксы-клик, `[[`-автокомплит с fuzzy, код-блоки, цитаты; raw-режим просмотра); палитра Ctrl+K (cmdk: заметки/команды/полнотекст со сниппетами и операторами `tag: status: updated:`); Quick Capture (глобальный хоткей, отдельное frameless-окно 480×160, трей-иконка с меню); панель свойств (frontmatter-форма: статус-пилюля, теги, приоритет, due, кольцо зрелости); вкладки + Ctrl+Tab; вложения Ctrl+V → `_assets/` с превью; настройки-минимум (vault, хоткеи, MCP-статус); мост Р6 (детект CLI, кнопки «Выжать»/«Распланировать» со spawn терминала, фолбэк-копирование).
**Критерии:** пользователь живёт в приложении как в основном заметочнике; 10k-дерево скроллится 60 fps; захват-окно < 150 мс; файлы, созданные из UI, байт-в-байт соответствуют формату (golden-тест).
**Пощупать:** красивый быстрый заметочник без ИИ-слоя; захват из любого приложения работает.

### Этап 4 — Live + доверие (2 нед)

**Задачи:** watcher (notify + debounce 300 мс + stability-check); эхо-подавление (path,hash TTL + сверка после стабилизации); live-reload (чистый буфер → тихий reload с сохранением позиции; грязный → секционный merge непересекающихся / баннер); журнал JSONL + zstd-снапшоты + undo операции/сессии (матрица §6.8); AI-лента (карточки, сессии, инлайн-диффы, семантические диффы планов, «Отменить»/«Отменить сессию», бейджи в дереве, полоска в заметке, пульс MCP); атрибуция user/assistant/external (Р27); тест-матрица конкурентности (VSCode, Claude Edit, git checkout, OneDrive, Defender).
**Критерии:** правка из Claude Code видна в открытой заметке < 1 с без прыжка курсора; любая операция откатывается одним кликом, сессия — одним действием; матрица конкурентности зелёная; ни одного случая потери правок в недельном догфуде.
**Пощупать:** агент пишет — текст «проявляется» на глазах с бирюзовой меткой; карточка в ленте; Undo работает.

### Этап 5 — Конвейер «идея → план» (1.5–2 нед)

**Задачи:** рендер плана (этапы, чекбоксы M16, прогресс-бар, блок «следующий шаг» на главном месте); доведение `plan_*`/`distill_*`/`context_briefing`/`tasks_query`/`task_check` до полного контракта; протокол интервью в промптах (≤7 вопросов, гипотезы, «реши сам», секция «Ты об этом ещё не думал»); кольцо зрелости с анимацией повышения; статус-конвейер в панели свойств и палитре; `ui_open_note`/`ui_flash_note`; недельное ревью и разбор инбокса end-to-end.
**Критерии:** **15-минутный тест выигран у «Obsidian + Claude Code» всухую** — свежий vault → искра хоткеем → одна команда → красивый интерактивный план с прогрессом, диффами и откатом, без единой настройки; S2–S13 проходят целиком.
**Пощупать:** флагманский сценарий от искры до плана — руками, на чистой машине.

### Этап 6 — Конфликты и стойкость (1 нед)

**Задачи:** конфликт-панель side-by-side (dirty + пересекающаяся внешняя правка), обе версии в истории; восстановление из `.trash` через undo-карточку; MAX_PATH-тесты (300+ символов, кириллица); стресс 10k заметок (рескан, поиск, память); «Пересобрать индекс» + индикатор свежести индекса в статусбаре; повреждение/удаление `.graphite/` → полное восстановление из файлов.
**Критерии:** матрица конфликтов зелёная; `del .graphite` → приложение восстанавливает всё за секунды без потерь; MAX_PATH и OneDrive-детект покрыты тестами.
**Пощупать:** намеренно ломаем всё подряд — приложение не теряет ни байта.

### Этап 7 — Полиш + упаковка (1.5–2 нед)

**Задачи:** мотион-каталог MVP (14 позиций §5.5) с reduced-motion; все пустые состояния §5.7; тосты/скелетоны; first-run flow §8.7 целиком; NSIS per-user + updater + релизный CI; иконка, трей-меню (захват, открыть, MCP-статус, выход); финальный проход по типографике и состояниям контролов.
**Критерии:** инсталлер ставится на чистую Win11 VM и проходит 15-минутный тест с нуля; автообновление прилетает; ни одного экрана, который стыдно показать на стриме.
**Пощупать:** подписанный инсталлер — личная бета v0.1.

**Итого MVP: 12–14 недель.**
